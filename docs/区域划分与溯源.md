# 区域划分与溯源

> **本文是项目的"分区宪法"**：哪些区域存在、各自管什么、谁维护、允许依赖谁、
> 每样东西如何追溯到来源、以及"今天是临时的、将来要换掉"的东西怎么标记。
>
> 制定日期：2026-10-08　｜　适用版本：玩法 v0.3.0 / 工程 v1.0.0
> 相关：[路线图](路线图.md)（下一步做什么）、[美术与GUI方案](美术与GUI方案.md)、[`../assets/README.md`](../assets/README.md)

## 一、为什么要有这份文档

项目里有两条线要同时往前走（**玩法线**与**美术/表现线**），而且将来还会加（音效、剧情、沙盘地图）。
如果不先分区，会出现三个必然的问题：

1. **改一个塌一片**：现在界面代码里写死了 41 处颜色、20 处字体 → 换一次皮要动 20 处代码；
2. **东西无处安放**：美术资产此前**没有任何目录**，只能塞进代码或临时扔在根目录；
3. **来源说不清**：用了别人的字体/图片，半年后既不知道来源，也不知道许可是否允许商用。

所以本文要立三件事：**隔离**（改一个不牵动另一个）、**可推进**（一个区域能独立往前走）、
**可溯源**（每样东西都能回答"哪来的、谁做的、什么许可、什么时候进来的、现在什么状态"）。

### 依赖方向（硬约束，由测试强制）

```
assets/  ──┐
config/  ──┼──►  ui/  ──►  （窗口）
src/     ──┘
   ▲
   └── src/ 不得依赖 ui/、assets/、config/ 以外的任何区域（引擎可独立运行）
```

- ✅ 允许：`ui/` → `src/`、`ui/` → `assets/`、`ui/` → `config/`
- 🚫 禁止：`src/` → `ui/`、`src/` → `assets/`（引擎不许依赖美术）、任何区域 → `tests/`
- 违反这条会被 `tests/test_architecture.py` 与 `tests/test_assets.py` 判红。

## 三、溯源四层机制

四层**全部启用**。每层落在具体的位置上，不是口号：

| 层 | 追问 | 机制落点 | 检查方式 |
| :--- | :--- | :--- | :--- |
| **A 来源可查** | 哪来的？谁做的？什么许可？什么时候进来的？ | `assets/manifest.json`（机器可读）+ `docs/资产来源与许可.md`（人可读，由脚本生成） | `python tools/资产台账.py 校验` |
| **B 变更可查** | 这个区域改过什么？ | git 历史按路径过滤：`python tools/区域日志.py 美术` | 提交信息前缀约定（见下） |
| **C 可替换可回退** | 换掉一个字体/配色，要改代码吗？ | 一切资产经 `assets/theme.json` 声明、由 `ui/资产.py` 解析；界面代码**禁止写死**颜色与字体名 | `tests/test_assets.py` 逐行扫描 `ui/*.py` |
| **D 归属可查** | 这是本人做的、AI 协作的，还是第三方的？ | 区域表「归属」列 + 台账每条的「作者」与「归属」字段 | 台账校验要求该字段非空 |

### 资产状态机（"今天临时的，将来换成自己的"）

每条资产都必须标当前状态，**让"临时物"一眼可见**，避免半年后自己都忘了：

```
占位 placeholder  →  过渡 interim  →  定稿 final
（能用就行）          （正式引入的替代品）    （本人原创或已确认长期使用）
```

配套字段：`替换计划`（写清"等什么条件满足就换成什么"）。字体就是最典型的例子。

### 提交信息前缀约定（服务于 B 层）

```
[引擎] ...      [数值] ...      [地理] ...      [美术] ...
[界面] ...      [文案] ...      [测试] ...      [文档] ...
[构建] ...      [归档] ...      [运行] ...      [全局] ...
```

前缀只用于**按区域检索历史**，不作为强制门禁（单人项目不做提交钩子）。

## 四、替换流程（以字体为例，完整走一遍）

这是本轮最想立起来的模式：**换一样东西 = 放文件 + 改一行声明，代码零改动。**

```
① 把新字体丢进 assets/fonts/            （文件名用「字库名-字重.ttf」）
② 在 assets/manifest.json 加一条记录      （名称/文件/来源/作者/许可/日期/校验值/状态/替换计划）
③ 在 assets/theme.json 改字体候选链       （把新字体放到第一位）
④ 跑 python tools/资产台账.py 校验        （确认来源与许可齐备、文件存在、校验值一致）
⑤ 跑 python run_tests.py --区域 美术       （确认界面能解析到该字体、且没有写死残留）
⑥ 提交：[美术] 引入本人隶书字库，替换过渡字体
```

**不需要改任何 `.py`** —— 这正是溯源 C 层（可替换可回退）的含义。
想回退：把 `theme.json` 的候选链改回去即可，旧文件与台账记录都在（必要时移入 `legacy/`）。

## 五、常用命令

```bash
python run_tests.py                  # 全部区域
python run_tests.py --fast           # 跳过旧自测全量回归
python run_tests.py --区域 美术       # 只跑与该区域相关的检查（互不干扰）
python tools/区域日志.py 美术          # 按区域看 git 历史（溯源 B）
python tools/资产台账.py              # 打印台账并校验（溯源 A/D）
python tools/资产台账.py 生成文档      # 重新生成 docs/资产来源与许可.md
```

## 六、纪律（改哪里、别改哪里）

1. **数值、地图、字体、配色、图片，一律不放代码里**：分别属于 `config/`、`assets/`。
2. **引擎不许碰美术**：`src/` 不得导入 `ui/` 与 `assets/`；引擎必须能脱离界面独立运行（并有测试证明）。
3. **界面不许含规则**：`ui/` 只能"渲染状态 + 送回玩家意图"，判定一律调 `src/`（已有回归用例：同策略打满 20 回合，
   界面路径与引擎主循环逐字段一致）。
4. **新资产必须进台账**：没有来源与许可的资产不允许入库（测试会拦）。
5. **临时物必须标状态**：任何"先用着、以后换"的东西，状态栏不能空。
6. **文档与代码一起改**：改了区域职责，同步更新本文件与对应区域的 `README.md`。
