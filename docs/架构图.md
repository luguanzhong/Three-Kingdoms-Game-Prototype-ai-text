## 一、总体分层

```mermaid
flowchart TB
    subgraph 入口["入口与日志（M5）"]
        CLI["argparse 命令行<br/>--version / --load / --demo<br/>--list-saves / --check-config<br/>--config / --log-level"]
        LOG["logging<br/>蜀汉突围 / .配置 / .存档<br/>默认 WARNING"]
    end

    subgraph 游戏["src/蜀汉突围.py（单文件三段式）"]
        M1["模块1 状态定义与初始化<br/>三势力 / 城池 / 将领 / 情报 / 全局 / 日期"]
        M2["模块2 确定性判定（纯函数）<br/>强攻·围攻·必败 / 攻城·伤亡 / 六种计谋<br/>有效兵力 / 势力值 / 冬季分档"]
        M3["模块3 主循环与事件<br/>决策阶段 → 结算回合(13步) → 打印局势<br/>→ 结局判定 → 推进日期"]
    end

    subgraph 配置层["配置层（M2）"]
        CFG["config/*.json<br/>units / schemes / seasons<br/>diplomacy / battle"]
        CL["src/config_loader.py<br/>深度合并 + 校验 + 明确报错<br/>非法即整体回退默认值"]
    end

    subgraph 存档层["存档层（M3）"]
        SM["src/save_manager.py<br/>采集/恢复 + 结构校验<br/>版本判定 + 原子写入"]
        SAVES["saves/*.json<br/>存档版本 1"]
    end

    subgraph 测试["测试体系（M4）"]
        RUN["run_tests.py<br/>一键入口（--fast）"]
        T1["tests/ 分类用例<br/>规则 / 边界 / 结局<br/>回归 / 架构"]
        T2["自测_确定性判定.py<br/>原 126 项断言（未改动）"]
        ARCH["零随机架构检查<br/>逐行扫描 + 报 文件:行号<br/>不导入随机库 / 仅标准库"]
    end

    CLI --> M3
    LOG -.-> M3
    M3 --> M2
    M2 --> M1
    M3 --> M1
    CL --> M2
    CFG --> CL
    SM --> SAVES
    M3 --> SM
    CL -.日志.-> LOG
    SM -.日志.-> LOG
    RUN --> T1
    RUN --> T2
    T1 --> 游戏
    T1 --> 配置层
    T1 --> 存档层
    ARCH --> 游戏
    ARCH --> 配置层
    ARCH --> 存档层
```

**依赖方向是单向的**：`入口 → 主循环 → 判定 → 状态`；`配置层 / 存档层` 被主循环读取，但不反向依赖游戏逻辑；
`tests/` 只读生产代码、不修改它们。这保证了"改配置不必改代码、改代码不会动存档格式"。

## 二、一次回合的流水线（结算回合 13 步）

```mermaid
flowchart LR
    A["决策阶段<br/>（玩家：每回合至多一件大事）"] --> B["1 曹魏增长"]
    B --> C["2 粮草消耗<br/>+冬季惩罚/粮荒"]
    C --> D["3 将领任务结算<br/>屯田/练兵/外交/子任务"]
    D --> E["4 东吴骑墙"]
    E --> F["5 田忌赛马"]
    F --> G["6 围攻推进"]
    G --> H["7 曹魏进攻"]
    H --> I["8 东吴背刺<br/>（亲魏且观望>85）"]
    I --> J["9 重伤恢复"]
    J --> K["10 民心恢复"]
    K --> L["11 连锁计时"]
    L --> M["12 阈值事件"]
    M --> N["13 东吴均势外交AI"]
    N --> O["清屏 + 打印局势<br/>（含战区态势图）+ 暂停 0.5 秒"]
    O --> P["结局判定"]
    P --> Q["推进日期<br/>月份+1 / 跨年 / 季节 / 冬至提醒"]
    Q --> A
```

零随机的实现要点：**A 由玩家决定，B~N 全是确定性公式与阈值比较，P 是四条硬条件**——
同一输入必然得到同一结果，因此 `tests/` 里可以直接断言完整 20 回合对局的结局与终局数值。

## 五、讲解提示（每层一句话）

1. **入口层**：命令行参数与日志都是薄封装，游戏逻辑一行没改；不带参数仍然是原来的交互启动。
2. **模块2（判定）**：全部是纯函数——给条件、出结果，没有随机源，所以可以被穷举测试。
3. **模块1（状态）**：全是模块级字面量，没有类、没有数据库，改初始值就是改字面量。
4. **配置层**：把"数值"从"逻辑"里搬出来，并给非法配置一套可读报错 + 整体回退。
5. **存档层**：只做"全局命名空间 ↔ JSON"的搬运与校验，不碰判定逻辑；版本不兼容明确拒绝。
6. **测试体系**：一键跑通，分类清晰，旧断言不丢；零随机是架构级约束而不是口头承诺。
