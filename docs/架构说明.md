# 蜀汉突围 · 架构说明

> 用途：让新接手的人（含未来的自己）在 2-3 分钟内理解本项目怎么组织、怎么跑、改哪里。
> 本文只描述代码现状，不含计划中的功能。

## 一、一句话架构

**单文件、纯标准库、三段式模块化**：`蜀汉突围.py` 按注释分隔为「模块1 状态定义与初始化 / 模块2 确定性判定 / 模块3 主循环与事件」，配套一个独立自测脚本 `自测_确定性判定.py`（83 项断言）。

## 二、代码分层（2-3 分钟讲稿）

1. **模块1 状态定义与初始化**：所有游戏数据都是字面量声明的全局变量——三势力字典（`蜀汉`/`曹魏`/`东吴`）、敌方城池字典（`敌方城池`）、蜀汉城池字典（`蜀汉城池`）、将领列表（`将领们`，每位将领是含统御/智谋/内政/忠诚/位置/任务/指令/子任务/状态等字段的字典）、情报字典（`情报`）、杂项状态字典（`全局`）、日期全局量（`当前年份`/`当前月份`/`回合计数`/`季节`）。没有类、没有数据库、没有配置文件，改初始状态就是改这里的字面量。
2. **模块2 确定性判定**：所有规则判定都是纯函数，输入明确条件、输出唯一结果，不读随机源、不掷骰。军事类（`计算强攻判定`/`计算围攻判定`/`计算必败判定`/`攻城结算`/`防御加成计算`/`城破伤亡判定`/`有效兵力计算`）、计谋类（`计谋_侦查粮道`/`计谋_劫粮道`/`计谋_侦查风向`/`计谋_火攻`/`计谋_据险而守`/`计谋_劝降`）、势力与季节类（`有进攻行为判定`/`计算势力值`/`蜀汉控制城池数`）都在这一层。
3. **模块3 主循环与事件**：`主循环()` 每回合按固定顺序执行「决策阶段（玩家输入）→ 结算回合（13 步自动推演）→ 清屏打印局势 → 暂停 0.5 秒 → 结局判定 → 推进日期」。菜单与展示（`决策阶段`/`军事行动菜单`/`计谋菜单`/`外交菜单`/`部署将领任务菜单`/`设定守城指令菜单`/`打印局势`/`绘制战区态势图`）、事件结算（`曹魏进攻结算`/`东吴背刺结算`/`阈值事件检查`/`东吴AI更新`/`攻占城池`）、结局（`结局判定`/`将领结局`）都在这一层。

## 三、一次回合的数据流

```
玩家输入 → 决策阶段（每回合至多一件"大事"：军事/计谋/外交；部署与设令不限次）
        → 结算回合：1 曹魏增长 → 2 粮草消耗与冬季惩罚/粮荒 → 3 将领任务结算
                    → 4 东吴骑墙 → 5 田忌赛马 → 6 围攻推进 → 7 曹魏进攻
                    → 8 东吴背刺 → 9 重伤恢复 → 10 民心恢复 → 11 连锁计时
                    → 12 阈值事件 → 13 东吴均势外交AI
        → 清屏 + 打印局势（含【战区态势图】）+ 睡眠 0.5 秒
        → 结局判定（命中则结束）→ 推进日期（月份+1、跨年进位、季节更新、冬至提醒）
```

## 四、零随机约束是怎么保证的

- 全文件**不含 `random` 字样**（自测脚本以 `"random" not in 源码` 作为一条断言，可随时用 `grep -i random 蜀汉突围.py` 复核）。
- 计谋不是概率事件：`计谋_*` 系列只检查前置条件（如 `情报["粮道情报"]` 是否为真、守将忠诚是否 <5、使臣智谋是否 ≥8），条件达成即 100% 成功，条件不满足即 100% 失败并提示缺什么。
- 军事行动只看数值比较：进攻兵力 > 守军×1.5 强攻必胜、>×0.8 可围攻、<×0.5 判定必败并禁止送死（唯一例外是"死士突袭"，其代价也是固定的）。
- 将领伤亡由玩家预设指令唯一决定（撤退/死守/默认驻守 → 固定结局），不存在百分比骰子。
- 数值层面的"连续变化"全部来自确定性公式（如有效兵力、防御加成、势力值、冬季系数）。

## 五、结局路径（4 条，均为硬条件）

| 结局 | 触发条件 |
| :--- | :--- |
| 北伐大捷 | `敌方城池["洛阳"]["归属"] == "蜀汉"`（最优先判定） |
| 星落秋风 | `蜀汉["兵力"] <= 0` 或 `蜀汉["魏国压力"] > 100` |
| 汉家尚有可为 | 撑满 20 回合且 `蜀汉["兵力"] > 初始兵力`（18000） |
| 中性结局 | 撑满 20 回合但兵力未超过初始值 |

## 六、测试体系

`自测_确定性判定.py` 不依赖 pytest，做法是：

1. 用 `importlib` 按路径动态加载 `蜀汉突围.py`（不会触发其主循环）；
2. **单元断言**：直接调用判定函数与计谋函数，验证前置条件成立/不成立时的确定结果；
3. **整局模拟**：把 `模块.input` 替换为脚本输入队列，用 `contextlib.redirect_stdout` 捕获输出，跑完三局不同策略的 20 回合对局，断言结局与关键中间状态；
4. 覆盖分组：军事/计谋确定性判定、精锐与子任务、城池与将领数据、洛阳与北伐大捷、月份与冬季惩罚、东吴均势AI、整局模拟、东吴背刺、零随机校验，共 83 项断言。

## 七、改动指引（改哪里）

| 想改什么 | 改哪里 |

| 初始数值/城池/将领 | 模块1 的字面量（并同步更新自测中的期望值） |
| 判定阈值与公式 | 模块2 对应函数（同步更新自测断言） |
| 每回合自动推演顺序 | 模块3 `结算回合()` 的编号步骤 |

| 展示格式（面板/态势图） | `打印局势()` / `绘制战区态势图()` |
| 胜负条件 | `结局判定()` |
