# 三国 · 蜀汉突围

**一句话定位**：一款以公元 208 年（建安十三年）赤壁前夕为背景、用**纯 Python 标准库**实现的单机回合制策略游戏原型——玩家扮演诸葛亮举荐的幕僚，在 20 个回合内通过内政、军事、外交与计谋带蜀汉寻找生机。

**核心亮点**

- **零随机**：全文件不含 `random` 字样，计谋与军事判定不看运气，只看前置条件与数值比较；玩家的每一步决策都因果明确、可复现。
- **确定性反馈 + 代价权衡**：条件达成即 100% 成功，收益必然伴随连锁代价（占城触发东吴忌惮与割地抉择、3 回合后曹魏增兵报复）。
- **将领生死由人**：没有年龄死亡与概率骰子，城破后将领结局完全由玩家预设指令决定（撤退 / 死守 / 默认驻守）。
- **无第三方依赖**：仅使用 `os` / `sys` / `time`，单文件约 1250 行，模块化三段结构，全中文注释与变量名。
- **随身自测**：配套 126 项断言的自动化自测脚本，含"零随机"架构级校验、配置合法性校验与存档往返一致性校验。
- **配置数据化（M2）**：兵种、计谋、季节、外交、战斗五类常量抽离到 `config/` 下的 JSON；改数值不必改代码，非法配置会给出明确报错并回退到内置默认值。
- **存档可续局（M3）**：版本化 JSON 存档（`saves/`），支持游戏内存档/读档菜单与 `--load` 命令行续局；损坏、缺字段、类型错、版本不兼容的存档只给可读提示，不会崩溃。

## 一、运行方法

### 环境要求

- Python **3.7 及以上**（本项目开发与验证环境：**3.13.1**）
- 不需要安装任何第三方库；不需要虚拟环境
- Windows 控制台建议使用 UTF-8 编码（程序已内置尽力而为的编码设置）

### 启动

```bash
# 方式一：已拿到项目文件夹
cd 三国test

# 方式二：从远程仓库克隆（把 <仓库地址> 换成实际地址）
git clone <仓库地址>
cd 三国test

# 运行游戏
python 蜀汉突围.py        # Windows 若提示找不到 python，可改用：py 蜀汉突围.py
python3 蜀汉突围.py       # macOS / Linux

# 从存档续局（读取 saves/<存档名>.json，默认名 save1）
python 蜀汉突围.py --load save1
python 蜀汉突围.py --help      # 查看命令行参数
```

### 示例操作

启动后先选运行模式：

- 输入 `1` → 扮演幕僚（交互决策），逐回合自己下指令
- 输入 `2` → 自动演示（默认策略推演 20 回合，无人值守，适合快速看效果）

交互模式下的回合菜单（可直接照抄体验）：

```
1. 部署将领任务（可多次）
2. 设定守城指令（可多次）
3. 军事行动【大事】
4. 计谋【大事】
5. 外交【大事/轻量】
6. 结束本回合决策，推进结算
7. 存档 / 读档【轻量】
```

每回合只能执行一件"大事"（军事 / 计谋 / 外交），部署与设令不限次；输入 `6` 结束决策，系统自动结算并清屏打印局势，等待 0.5 秒后进入下一回合。
第 `7` 项是存档 / 读档（轻量操作，不占用"大事"名额），见「存档说明」。

### 如何新增回归用例

1. 在 `tests/test_regressions.py` 里加一个 `test_regression_<模块或阶段>_<现象>` 方法；
2. docstring 写明来源（真实缺陷就写 CHANGELOG/提交线索，边界加固就写"边界固化"），**不要编造历史**；
3. 用 `夹具.载入游戏()` / `夹具.载入配置模块()` / `夹具.载入存档模块()` 取得干净状态，避免用例间互相影响；
4. 跑 `python run_tests.py --fast` 快速验证，提交前再跑一次完整 `python run_tests.py`。

### "零随机"架构检查

由 `tests/test_architecture.py` 承担，扫描范围是生产模块 `蜀汉突围.py` / `config_loader.py` / `save_manager.py`：

- 逐文件逐行匹配 **13 个随机关键字**（`random`、`randint`、`randrange`、`shuffle`、`choice`、`choices`、`uniform`、`sample`、`getrandbits`、`seed`、`secrets`、`urandom` 等），命中时报告 `文件:行号: 内容`；
- 额外检查不得出现 `import random` / `from random` / `import secrets` 等导入；
- 依赖白名单检查：生产模块只允许标准库与本地模块（`config_loader`、`save_manager`）；
- 行为级校验：判定函数对同一输入连续调用结果必须完全一致，两次独立加载的初始状态必须相同。

> 白名单说明（记录原因）：`蜀汉突围_*备份.py` 是历史版本快照、不参与运行，扫描它只会产生噪声，故排除；`tests/` 下的测试代码本身需要写出这些关键字（用于断言"生产代码不含这些关键字"），因此不纳入扫描。原 `自测_确定性判定.py` 中的 3 条子串式零随机断言也全部保留。

## 三、配置说明（M2 新增）

兵种参数、计谋条件、季节惩罚、外交阈值与战斗阈值已从代码抽离到 `config/` 下的五份 JSON。
**改数值只需改配置文件，不必碰 `蜀汉突围.py`**；配置可缺省——文件缺失或内容非法时会回退到
`config_loader.py` 的内置默认值（与抽离前逐位一致），所以默认行为与原版完全相同。

| 配置文件 | 合并后路径 | 管什么 |
| :--- | :--- | :--- |
| `config/units.json` | `配置["兵种"]` | 精锐比例上限与练兵加成、有效兵力系数（基准/分母）、募兵兵力与粮草代价 |
| `config/schemes.json` | `配置["计谋"]` | 侦查粮草成本、劫粮道与火攻的系数/粮草/倾向削减、据险而守的前置任务与险关地形、劝降的忠诚上限与智谋下限 |
| `config/seasons.json` | `配置["季节"]` | 季节月份映射（1~12 月须不重不漏）、冬季粮草系数与冻伤比例（有进攻/退守两档） |
| `config/diplomacy.json` | `配置["外交"]` | 势力值权重、亲魏/亲蜀/观望的势力比阈值与每回合增减、密使与盟约阈值、结盟与背刺参数 |
| `config/battle.json` | `配置["战斗"]` | 强攻/围攻/必败/破城倍率、损失与收编系数、防御加成、守军比例、入侵系数、死士突袭、北伐大捷 |

### 怎么改数值

1. 打开对应 JSON，改数字并保存（UTF-8 编码）。
2. 自检：`python config_loader.py` —— 通过时打印"通过"，否则逐条列出问题。
3. 直接运行游戏即生效（`险关位置`等在启动时读取，改后需重开进程）。

### 校验规则（非法配置会给出明确错误，不会崩溃）

- **类型**：数值字段必须是整数/小数（拒绝字符串与布尔）；列表字段必须是列表且元素为字符串
- **范围**：每个数值字段都有上下限（如 `强攻.损失系数` 0~2、`精锐.比例上限` 1~100）
- **枚举**：`据险而守.前置任务`、`背刺.触发倾向` 只能取代码认识的取值
- **引用**：`劫粮道.前置情报` 与 `火攻.前置情报` 必须存在于 `计谋.情报键名`
- **一致性**：`必败上限 < 围攻下限 < 强攻下限`、`密使阈值 < 盟约阈值`、`亲蜀上限 < 亲魏下限`、`练兵加成 ≤ 比例上限`
- **季节覆盖**：`季节月份` 必须把 1~12 月不重不漏地分配给四个季节，且季节名必须是 秋/冬/春/夏
- **未知字段**：写了代码不认识的字段会提示"可能是拼写错误"

### 非法配置示例（真实报错）

把 `config/battle.json` 的 `强攻.损失系数` 改成字符串 `"很痛"` 后运行游戏：

```
【配置警告】检测到 1 处配置问题：
  · config/battle.json → 字段 "战斗.强攻.损失系数"：期望 0~2 的整数或小数，实际 '很痛'（字符串）
  提示：修改 config/ 下对应文件后重新运行；或执行 python config_loader.py 单独校验；删除 config/ 可回退内置默认值。
  （本次运行使用内置默认配置，行为与原始版本一致）
```

单文件缺失、JSON 语法错误、范围越界、引用不存在、季节覆盖不全、字段拼写错误同理，都会指出**文件 + 字段 + 期望 + 实际**。
在测试/CI 中可调用 `config_loader.载入配置(严格=True)` 直接取到 `配置错误` 异常文本。

> 范围说明：结算经济数值（曹魏增长率、粮草消耗基数、粮荒阈值、压力增减、阈值事件、连锁计时、民心恢复）
> 与任务名枚举仍在代码中，属于 M2 范围之外，见「已知限制」。

## 四、存档说明（M3 新增）

### 存档位置与格式

- **位置**：项目根目录下的 `saves/`（首次保存时自动创建），文件名 `<存档名>.json`，默认存档名 `save1`。
- **格式**：可读的 **JSON**（UTF-8、缩进 2 空格），可直接打开查看或手工比对；`saves/` 已在 `.gitignore` 中排除，不会提交进仓库。
- **版本字段**：顶层 `存档版本`（当前 **1**）与 `游戏版本`（如 `v0.3.0`）；另含 `保存时间`、`日期`、`三方势力`、`敌方城池`、`蜀汉城池`、`将领们`、`情报`、`全局`。
- **保存内容**：年月 / 回合 / 季节、三方势力全部数值、城池（归属 / 驻军 / 粮草 / 守将）、全部将领（含劝降新增将领及其状态·任务·指令·子任务）、情报、围攻状态、事件日志、连锁计时、结盟与外交倾向等。
- **不写入存档**：`总回合数`、`初始兵力`、`险关位置`、`配置`——这些由代码或 `config/` 决定。

### 如何保存 / 加载

| 方式 | 操作 |
| :--- | :--- |
| 游戏内存档 / 读档 | 决策菜单输入 `7` →【存档 / 读档】：`1` 保存（可输入存档名，回车默认 `save1`）、`2` 读取、`3` 列出全部存档 |
| 命令行续局 | `python 蜀汉突围.py --load <存档名>`（不带参数仍是新开局） |
| 函数调用 | `save_manager.保存游戏(globals(), "save1")` / `save_manager.载入游戏(globals(), "save1")` |
| 查看存档列表 | `python save_manager.py` |

**完整流程（保存 → 退出 → 重载 → 继续同一局）**：游戏内 `7 → 1` 存档 → 关闭程序 →
`python 蜀汉突围.py --load save1` → 程序打印恢复到第几回合、何年何月，并从该回合继续；由于游戏零随机，续局结果与不中断的一局完全一致（自测中已断言）。

### 异常与兼容策略（都给可读提示，绝不抛 traceback）

- **文件不存在**：`读取失败：存档不存在，文件 saves/xxx.json；可用「列出存档」查看现有存档，或先「保存当前进度」。`
- **JSON 语法错误**：`存档损坏：JSON 解析失败（第 N 行第 M 列：原因），文件 …；该文件可能被手工改坏或写入中断，建议删除后重新保存。`
- **缺字段 / 类型错**：逐项列出，如 `缺少字段 将领们`、`日期.回合计数 应为整数，实际 '三'（字符串）`，并附文件路径。
- **权限 / 磁盘问题**：`保存失败：无法写入存档文件（原因），路径 …；请检查目录权限或磁盘空间。`
- **读档失败不影响当前局面**：校验不通过时不会改动任何游戏状态（自测已断言）。
- **版本兼容**：`存档版本` 与当前支持版本不一致时明确指出 `存档为旧版本（存档版本 0，本程序支持 1）` 或 `存档来自更新的程序版本` 并拒绝读取；迁移钩子 `save_manager.迁移表` 已预留（当前无历史版本，故为空，属"明确拒绝"策略）。
- **原子写入**：先写 `.tmp` 再 `os.replace`，写入中断不会破坏已有存档。
- **手工改坏也不怕**：`python save_manager.py` 会列出每个存档的状态（正常 / 损坏及问题数）。

> 限制：存档不记录 `config/` 内容；若在保存与读取之间修改了配置，续局将按**当前**配置运行。

## 五、核心规则（速览）

- **零随机**：无随机库调用。计谋 = 前置条件检查（有情报才可劫粮道、守将忠诚<5 且使臣智谋≥8 才可劝降）；军事 = 数值比较（进攻兵力 > 守军×1.5 强攻必胜、>×0.8 可围攻、<×0.5 判必败并禁止送死）。
- **状态定义**：三势力字典 + 敌方城池字典 + 蜀汉城池字典 + 将领字典列表 + 情报字典 + 杂项状态字典 + 日期全局量（年/月/回合计数/季节）。全部为模块级字面量，无类、无存档文件。
- **确定性判定**：模块2 全是纯函数，输入条件输出唯一结果；将领伤亡、冬季冻伤、势力值、有效兵力均为固定公式。
- **主循环分层**：决策阶段（玩家）→ 结算回合（13 步自动推演：曹魏增长 → 粮草与冬季 → 将领任务 → 东吴骑墙 → 田忌赛马 → 围攻 → 曹魏进攻 → 东吴背刺 → 重伤 → 民心 → 连锁计时 → 阈值事件 → 东吴AI）→ 打印局势 → 结局判定 → 推进日期。
- **结局路径**：北伐大捷（洛阳归蜀）＞ 星落秋风（兵力归零或压力 >100）＞ 汉家尚有可为（20 回合且兵力 >18000）＞ 中性结局（20 回合但兵力未超初始值）。

完整规则表见 [`docs/规则说明.md`](docs/规则说明.md)。

## 八、架构简述（2-3 分钟能讲清的版本）

1. **单文件三段式 + 一层配置**：`蜀汉突围.py` 用注释分成三个模块——模块1 只放状态字面量（三势力、城池、将领、情报、全局杂项、日期），模块2 只放纯判定函数（军事、计谋、势力与季节），模块3 只放主循环、菜单、事件结算与显示；**数值参数由 `config_loader.py` 从 `config/*.json` 载入并校验**，代码只读配置不再写死数字。
2. **主循环是一个固定流水线**：决策阶段（玩家，每回合至多一件大事）→ 结算回合（13 步顺序固定）→ 打印局势 → 结局判定 → 推进日期，因此"同一输入必然得到同一结果"。
3. **零随机靠三件事保证**：不引入随机库、计谋只做前置条件检查、军事只做阈值比较；并且自测里有一条架构级断言——源码中不得出现 `random` 字样（主程序与配置加载器都校验）。
4. **数据与展示分离**：`打印局势()` 与 `绘制战区态势图()` 只读状态、不写状态，态势图按归属动态渲染（【魏】/【蜀】前缀、守将与任务、险关★、东线要塞◆、首都洛阳）。
5. **测试是"注入式"的**：自测脚本用 `importlib` 动态加载游戏模块（不触发主循环），把 `input` 换成脚本队列、把输出重定向到内存，既能单元断言判定函数，也能跑完整 20 回合对局并断言结局；配置部分用临时目录造出各类非法配置，存档部分用临时目录做保存→篡改→读档的往返比对与损坏注入。
6. **存档是一层薄适配器**：`save_manager.py` 只做「模块全局命名空间 ↔ JSON 字典」的采集/恢复与校验，不改动任何判定逻辑；恢复时容器原地清空重填、标量写回命名空间，因此读档后各函数读到的就是新状态。

更详细的分层与数据流说明见 [`docs/架构说明.md`](docs/架构说明.md)。

## 九、已知限制（当前不做什么）

- 无图形界面，只有控制台交互；不支持鼠标操作。
- **配置覆盖范围有限**：结算经济数值（曹魏增长率、粮草消耗基数、粮荒阈值、压力增减、阈值事件、连锁计时、民心恢复）、任务名枚举、城池与将领数据、结局阈值仍在代码中，需改代码而非配置。
- 配置为整体校验：任一处非法即整体回退内置默认值（不做"部分生效"），以行为可预期为优先。
- **存档范围有限**：单存档目录（`saves/`）、无自动存档、无云同步；不记录 `config/` 快照，因此改配置后续旧档会按新配置运行；存档不校验"字段是否多余"，手工新增的未知字段会被原样保留。
- 固定 20 回合上限，无自由模式、无难度选择。
- 单机本地运行，无联网、无排行榜、无多人。
- 测试是自研的注入式自测 + unittest 分类用例，**没有 CI 配置**（一键入口 `run_tests.py` 已可直接接入 CI，退出码可用于门禁）。
- 仅中文一种语言；无音效与美术资源。
- 根目录同时存放着历史版本快照与另一独立工程目录 `地图/`（后者已被 `.gitignore` 排除，不属于本项目）。
- `待实现构想.txt` 中的内容均为**未实现**的设想，不代表现有功能。
